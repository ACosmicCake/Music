# Notes for agents

The app is in `world-woodshed/`, a Vite project with plain JavaScript ES modules and no framework. It is an installable PWA (vite-plugin-pwa) deployed to GitHub Pages by `.github/workflows/deploy.yml`.

Run `npm install` then `npm run dev` (or `npm run build && npm run preview` to test the service worker) inside `world-woodshed/`, and drive it with Playwright to check a change. `npm test` (Vitest, `test/`) covers state migration and device merging (`src/sync.js`), chord parsing and diatonic harmony (`theory.test.js`), the skill model and backups (`engine.test.js`), the memory model and session planner (`curriculum.test.js`), routine time fitting (`routines.test.js`), practice statistics (`stats.test.js`), your own tunes (`mytunes.test.js`) and the reading library (`readlib.test.js`), and checks the content data (rhythm lengths, chord symbols, drill bars, reading generators). `npm run lint` runs ESLint (`eslint.config.js`: `eslint:recommended`, with unused names as warnings); both workflows run lint and tests before building. Tests that load `engine.js` import `test/env.js` first (an in-memory `localStorage` and a stub `document`) and pin the clock with `vi.setSystemTime`.

## Files

`src/main.js` imports everything in order and boots the app:

- `index.html`: page shell only.
- `src/styles.css`: all CSS (design tokens on `:root`, dark mode via `prefers-color-scheme` and `data-theme`). Fonts are bundled from `@fontsource` so the app works offline. A compact layout for small phones (3-inch screens such as the Unihertz Jelly Star) lives under `html.compact`, set by `applyDisplay()` in `src/ui/core.js`: automatic below 380 × 640 CSS px or chosen in Train → Display, with a text size (`html[data-text]`); both are per device (`DEVICE_SETTINGS`). Check new UI at 240 px wide as well as on a normal phone.
- `src/data.js`: content. Intervals and anchor songs, chords, progressions, world scales and ragas/maqamat, rhythm cycles, tunes, grooves, technique exercises, styles (atlas regions). It merges in `src/content/`.
- `src/content/`: long-form content. `styles-a.js`, `styles-b.js` (deep-dive fields for the original regions: history, sub-styles, how it works, listening path, players, study, practice) and `styles-new.js` (eight whole new styles); `lessons.js` (the theory course); `rhythms-new.js` (more rhythms per style, appended to `RHYTHMS`) and `rhythms-var.js` (variations, fills, cycles, tempo range and tips for every rhythm, attached as `r.var`; the player's own part never changes in a variation); `drills-a.js`, `drills-b.js` (four style drills per style, `D.DRILLS`); `exercise-vars.js` (variations, speed burst and listening cue per technique exercise, `ex.vars`); `gym.js` (the rhythm gym: tuplets and polyrhythms). Keep recordings, years and books accurate. Content only some pages show is loaded on demand by `lazy.js` (`loadEssays` for the style essays in `essays-*.js`, `loadScience`, `loadGuides`, `loadDrills`, `loadLessons`; draw with `whenLoaded` for a page or `drawWhenLoaded` inside a tool) so it stays out of the first download; dynamic `import()` chunks are still precached, so they work offline. `D.TECHNIQUES`, `D.DRILLS` and `D.LESSONS` start as a build-time index of their short fields (`virtual:content-index`, made by `scripts/content-index.mjs` from the content files; the fields are listed in `INDEX_FIELDS`) and the full objects are merged in when loaded: code that reads a long field (a guide's `mechanics`, a drill's `variations`, a lesson's `body`) must load first.
- `src/theory.js`: chord-symbol parsing, note spelling, diatonic chords. `chordMidis` is close position, kept for ear training.
- `src/voicings.js`: guitar chord shapes on the current tuning and capo (`voicings` lists playable shapes best first; `guitarMidis` and `progressionMidis` give the notes to strum, the latter staying near the last chord). Used by the chord demos (explorer, circle of fifths, lessons, repertoire), not by the ear trainers. `test/voicings.test.js` checks every chord on every root and tuning.
- `src/curriculum.js`: the smart practice engine. Every content item (scale on the neck, technique, rhythm, tune, lesson) has a memory stability in days (FSRS-style recall curve); it plans a session for the minutes the player has now, taking earlier sessions that day into account, caps new material per day, follows the player's ranked styles, rotates warm-up key/pattern/position/tempo, and grades blocks from tool signals (`hooks.signal(itemId, data)`) or a one-tap rating. Parameters follow `src/content/science.js` (verified research, shown in the app).
- `src/notation.js` (SVG staff renderer, no fonts), `src/content/reading.js` (16 sight-reading levels and generators) and `src/tools/reading.js` (the Sight-reading tool: notes, rhythm, melody, with mic scoring). `src/readlib.js` keeps every generated rhythm and melody you read (compactly encoded, in `state.readLib`); missed ones come back for a re-read after a gap, one piece in three, and you can star, replay or delete them.
- `src/routines.js`: routine block types (`BLOCKS`), templates, time fitting (`setTotal`, auto breaks), no-guitar swaps (`awayBlocks`).
- `src/audio.js`: Web Audio synthesis (Karplus-Strong guitar, percussion voices, look-ahead `Loop` scheduler, tanpura `Drone`). `note`, `strum` and `hit` take an optional output node. `strum` is humanised (`strumPlan`: 8–25 ms per string, `o.dir: 'up'` strokes, a few cents of detune, all strings damped together); `note` takes `o.detune` (cents) and `o.release` (seconds). Output chain: `note` plays on a guitar channel and `hit` on a percussion channel (`A.channel(name)`: level, slight stereo placement, a send to a shared 0.5 s room reverb), then master, the compressor (the only look-ahead node, so latency stays as it was) and a soft limiter (a WaveShaper fed at a quarter level so its curve covers ±4 × full scale, unchanged below −3 dBFS). The context's `latencyHint` comes from `settings.audioOutput` (per device, Train → Display → Sound output; `latencyHintFor`): `auto` asks for `playback` on Android, whose default low-latency path crackles on some phones, and `interactive` elsewhere; it is read once, when the audio starts. `test/output.test.js`. The band and the sampled instruments keep their own buses into master.
- `src/samples.js`: sampled instruments. Each instrument (`src/content/samples.js`, generated) loads on first use with fetch + decodeAudioData; `play(id, midi, when, vel, dur, out)` returns null until it has, and the caller plays its synth voice instead. Velocity layers, round-robins, nearest sampled pitch, attack found in the decoded audio. The files live in `public/samples/<id>/` (mono 44.1 kHz MP3), credited in `public/samples/LICENSES.md` (CC0 or CC-BY only) and built from the recipes in `scripts/samples/recipes.mjs` by `scripts/samples/build.mjs` (needs ffmpeg). The service worker caches them at runtime (cache `ww-samples`), not in the precache; Train → Display → Sounds downloads them all. `test/samples.test.js` checks every file exists, is mono 44.1 kHz MP3 and has a licence entry.
- `src/guitars.js`: the recorded guitars behind `A.note()` (so every strum, fretboard tap, ear-training note and the band's guitar comping), registered with `A.setNoteSampler`. `settings.guitarSound` picks `nylon` (default), `steel` or `synth` (Train → Display → Sounds); the recordings (FluidR3 GM, one velocity per semitone, CC BY 3.0 renders of an MIT SoundFont) are made darker as well as quieter for soft notes (`cutoffFor`). `A.note(…, { synth: true })` skips them. Loaded on the first tap; the synth plays until then. `test/guitars.test.js`.
- `src/drumkit.js`: the recorded percussion behind `A.hit()` (registered with `A.setHitSampler`). Maps each voice to a sample set, with low/mid/high chosen by the rhythm's region (`kitFor`: congas for Cuba and West Africa, darbuka for Arabic, Turkish/Balkan and Persian, cajón for flamenco, drum kit elsewhere). The tabla and the chick (a guitar chop) stay synthesized. `prepare()` loads a rhythm's sounds when it is shown; the metronome's woodblock loads on the first tap. `hit(type, when, vel, out, { kit, region, synth })`; mic calibration forces the synth click. `test/drumkit.test.js` checks every voice has a recording.
- `src/band.js`: the Repertoire gym's backing band (`Band`). Swing: walking upright bass, rootless piano voicings with voice leading and varied comping rhythms, synthesized ride kit; bossa nova; other grooves from the `GROOVES` patterns. Parts sit on a bus with room reverb and can be muted (e.g. bass alone). `barAt(time)` drives the "follow the form by ear" check. Tunes can carry a `form` (`[[label, bars]]`) in `data.js`.
- `src/engine.js`: your guitar (`TUNINGS`, `STRINGS` updated in place for tuning and capo, `setGuitar`; left-handed fretboard; letter or solfège note names applied to `D.NOTE_NAMES`), skill model, spaced repetition, mastery and level unlocks, placement test, the adaptive (smart) plan, custom routines, the running session, lessons done, recordings heard, practice journal, persistence, backup export/import.
- `src/ui/core.js`: UI helpers (`h`, `s`, `Fretboard`, `toast`, `Quiz`), tabs and routing (old `#ear`, `#rhythm`, `#play`, `#atlas` links are aliases), the tool registry (`tool`, `openTool`), placement runner. `PAGES` lives here and is filled in by the page modules; `hooks` lets `session.js` plug in without import cycles.
- `src/ui/session.js`: the practice session runner: wall-clock timer that keeps counting with the screen off, session bar on each tool, time-up chime and auto-advance, wake lock, finish screen and journal.
- `src/ui/smart.js`: the smart planner ("How much time do you have right now?"), learning preferences (ranked styles, pace, daily goal) and the science page.
- `src/ui/routine.js`: the Routine tab (routine editor with drag reorder, durations, templates, smart plan, session overview).
- `src/mytunes.js`: your own tunes for the Repertoire gym. Reads a typed chord chart (bars split by `|` or lines, `%` repeats a bar, common spellings such as `C-7`, `CΔ7`, `Cø` normalised to `theory.js` symbols) and form (`AABA` or `A8 B8`), checks a draft (`checkTune`) and makes a saved tune safe to play (`playable`, since it may come from another device). Saved in `state.tunes` (`E.listTunes`, `saveTune`, `deleteTune` with a `tune:` tombstone) in the same shape as `D.TUNES`, so the Repertoire gym and the band play them alike; they are not in the planner's catalogue, so they send no `hooks.signal`. A Transcribe song becomes a draft tune (Sections card → "Make a tune for the band"): `songLayout` turns the beat grid and sections (or the loop, or the whole song) into bars and a form, the Transcribe plugin guesses a chord per bar or half bar from the recording (`songChords`, using `splitBar` and `chordName`) and opens the Repertoire editor with `params.draft`; the saved tune keeps the song's id in `song` for the link back.
- `src/tools/ear.js`, `rhythm.js`, `play.js`, `atlas.js`: trainers, registered with `tool(id, def)`. Ear tools accept `params.contrast: [a, b]` (a contrast drill on two confused items, started from Today's weak spots); the scale explorer compares quarter-tone maqamat with their 12-TET rounding.
- `src/tools/dictation.js` (+ `dictation.css`, items and melody generator in `src/content/dictation.js`): Melodic dictation, skill `dictation`.
- `src/tools/practice.js`: scale warm-up, chord & scale explorer, circle of fifths, reference tones, free practice, break, no-guitar drills.
- `src/tools/learn.js`: the Learn tab (style library and style pages, theory course and lesson reader, reference) and the `listening` and `lesson` tools.
- `src/spotify.js`: the Spotify links on listening-path albums and songs (style pages and the Active listening tool). No API or account: a search for the artist and record (`spotifyQuery` trims bracketed notes and long lists of names). On Android (the app or Chrome) a tap opens the Spotify app with a `spotify:search:` link and falls back to `open.spotify.com` if nothing took over; elsewhere it is a plain link to the web player. `test/spotify.test.js`.
- `src/tools/transcribe.js` (+ `transcribe.css`): the Transcribe tab, a plugin that receives the `UI` object. It is its own chunk: `transcribe-lazy.js` registers the tab, icon and a stand-in tool at boot and loads the real plugin the first time either is opened. Key and tempo estimates on load, a beat grid with snap-to-beat loops, the note at the playhead, Media Session controls and a screen wake lock while playing.
- `src/pages.js`: the Today dashboard and the Train page.
- `src/stats.js` (plain functions over `state.hdev` and `state.skills`: weeks of minutes and answers per skill across devices, accuracy change, quiz items due by a time, time on each scale (`scaleTotals`, `scaleTimeOf`); tested in `test/stats.test.js`) and `src/ui/stats.js` (the Statistics page, opened from Today → Progress → All statistics: minutes and accuracy per skill per week, time on each scale and key, the six-month heatmap, and what is due by tomorrow night from `Cur.dueAt`, the planner's own due rule).
- `src/goals.js` (plain functions, `test/goals.test.js`): streaks by the player's rule (`prefs.streakRule`: any practice, n minutes or the goal), the goal that held on each day (`prefs.goalLog`, so raising the goal keeps the days already met) and the growing goal (`ramp`: after a week at one goal met on 5 of 7 days it goes up 10%, at least 10 minutes, toward `prefs.goalTarget`, 4 h unless set; never down by itself). `E.streaks()` adds the best streaks ever, kept in `state.records` (merged by max). `src/ui/goal.js` draws the goal card on Today (and grows the goal when it is time, `applyRamp`) and the goal settings, also in Your learning plan.
- Time on each scale: `E.addScaleTime(kind, scale, tonic, sec)` keeps seconds seen in your head (`v`, No-guitar drills → See the neck in your head) and played (`p`, Scale warm-up) per device in `state.scaleTime` (`{ device: { 'scale:tonic': { v, p, last } } }`, never pruned; merged by the bigger number). Both tools count with `scaleClock` in `src/tools/practice.js`: wall-clock while the click runs, the screen kept on, a sleep gap counted as two minutes at most. The Today heatmap and 14-day chart live in `src/ui/stats.js` too.
- `src/stretch.js` (phase-vocoder time-stretch with phase locking, transient resets and shared stereo phase; windowed-sinc resampler for pitch shift) and `src/stretch.worker.js` (runs it in a module Worker).
- `src/listen.js` (pitch and onset detection, the `Mic` input and its latency calibration) and `src/ui/mic.js` (the Listen toggle, mic settings card, timing meter).
- `src/pwa.js`: service worker registration, update banner, install banner.
- `src/native.js`: the Android app's native bits with web fallbacks (`shareFile`, `keepAwake`, `speak`, the back button); plugins are imported only inside the app. `src/tools/commute.js` (+ `commute.css`): On the go (ride-length no-guitar session: the smart plan with the kinds of practice you include, or your own commute, both editable; plans from `src/commuteplan.js` (`commuteBlocks`, `planRide`, `mineBlocks`; `test/commuteplan.test.js`), hands-free ear training with spoken answers and tap or headphone-button grading; what to ask, answer time, stop-after and play-twice are settings in `settings.commute`).
- `android/`: the Capacitor Android project (generated by `npx cap add android`, then edited: permissions in `AndroidManifest.xml`, signing (a private key from repository secrets, never committed; debug key otherwise) and `versionCode` in `app/build.gradle`, icons drawn by a script). `npm run android:sync` builds the web app and copies it in. The Android SDK isn't reachable from cloud sessions, so the APK is built by `.github/workflows/android.yml`.

## Conventions

- No frameworks and no runtime requests to other sites; everything is bundled so it works offline. The one exception is opt-in: automatic sync through the player's own private GitHub repository (`src/ghsync.js`), which talks only to `api.github.com` with a fine-grained token kept in this device's `localStorage` (key `ww-gh-sync`), never in the state, sync files or backups.
- New tabs or tools can be added as a plugin: export a function that takes the `UI` object and add it to the list in `src/main.js` (pushing onto `window.WW_PLUGINS` still works too).
- Persistence: `engine.js` saves state to `localStorage` and a copy in IndexedDB, and asks for persistent storage. When `window.claude` exists (inside a claude.ai Artifact with the `db` and `user` capabilities), it also syncs to the private database (chunked under `data/users/<id>/`, live across devices). Keep that guard.
- Saved state has a `schema` number. Changing its shape means adding a migration in `src/sync.js` (`MIGRATIONS`), never dropping old data, and teaching `merge()` about any new top-level key. A failed save is tracked in `engine.js` (`saveHealth`, `onSaveHealth`: `ok`, `idb-only` when localStorage fails but IndexedDB has it, `failing`, plus `stale` after a day without a good save) and shown as one quiet banner by `src/ui/savebanner.js`; `test/persistence.test.js` loads a saved state from every past schema (`test/fixtures/save-schema-*.json`; add one when you add a schema). Every copy (IndexedDB, cloud, sync file) is merged, not overwritten: practice time is kept per device in `state.hdev` and `history` is rebuilt from it; deletions leave a tombstone (`E.tombstone`). Device-only settings (latency, mic) are listed in `DEVICE_SETTINGS`.
- Transcribe stores loaded audio in IndexedDB on the device only; song setups save with the rest of the state.
- Text from the player or another device (journal notes, song titles and links, routine names, anything in an imported backup or sync file) is only ever set with `h()`/`textContent`, never parsed as HTML; `innerHTML` is only cleared or set to a bundled SVG icon (`test/safety.test.js` checks this). Links from saved data are opened only if they are `http(s)`.
- Microphone input is opt-in. `src/listen.js` analyses it on the device (pitch, note onsets with exact timing); nothing is recorded or sent. Tools subscribe with `Mic.on(type, fn)` and the mic closes when the last listener unsubscribes. Every mic feature must also work by tapping.
